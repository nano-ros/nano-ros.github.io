## What nano-ros is

**nano-ros** is a deterministic ROS 2 client library for microcontrollers and RTOS-based systems. It implements `ros2_control` hardware interfaces natively on the RTOS — the microcontroller or FPGA becomes a first-class ROS 2 node, not a dumb serial endpoint managed by a Linux host.

**ros2_HDL** is the code-generation companion. It reads a VHDL entity port map and a URDF `<ros2_control>` block and generates the C `hardware_interface` binding, unit scaling, and CCSDS APID assignment. The register map is never written twice.

## The gap nano-ros fills

| Gap | Solution |
|---|---|
| micro-ROS has no `ros2_control` on any RTOS | nano-ros exposes `hardware_interface` natively on the RTOS |
| Space ROS has no embedded firmware layer | nano-ros space tier on RTEMS + SpaceWire / CCSDS transport |
| FPGA register maps maintained in HDL and C separately | ros2_HDL generates the C binding with unit scaling from VHDL source |
| No hardware guardian for FPGA radiation resilience | Independent MCU companion: boot, scrub, latch-up protection, watchdog reset |

## Two deployment contexts

nano-ros targets two hardware profiles that share the same architecture and firmware source.

**Space and safety-critical** — RTEMS 6 on LEON3/4/5, NOEL-V, and PolarFire SoC. SpaceWire/CCSDS transport. GRLIB IP cores. Radiation-tolerant hardware. ESA and NASA qualification path.

**Industrial embedded** — Zephyr on NeXCon PolarFire SoC and standard Cortex-M/RISC-V MCUs. zenoh transport. GoMyRobot HELIX-7 reference deployment.
